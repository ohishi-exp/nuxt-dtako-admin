# 拘束時間 → 時間給計算の仕様 (restraint-wage)

/restraint-wage (拘束・賃金) の時間給計算・最低賃金チェックが「何を・どう計算しているか」の
仕様まとめ。実装は `workers/dtako-scraper-relay/src/restraint-wage.ts` (pure ロジック、
coverage 100% gate 対象)、表示は `app/pages/restraint-wage.vue` /
`app/components/RestraintWageMonthlyTable.vue`。

Refs #244 (時間給計算の導入), #253 (給与比較・最低賃金), #268 (タブ分離), #278 (支給項目5区分化),
#282 (時給列廃止・計算単価表示・最低賃金換算表示の全廃)

## 1. 位置づけ — 理論値の事前チェックであって支払い実績の検証ではない

ここで計算する金額はすべて **「単価マスタ (会社が登録した基本時間単価) × デジタコ拘束時間」の
理論値**。実際に振り込まれた給与 (支払い実績) ではない。

- 目的: **単価マスタの設定自体が最低賃金水準を満たしているか**を、同じ式で計算した
  「単価マスタ換算」と「最低賃金換算」の理論値同士で比較する (レート設定の事前チェック)。
- 支払い済み金額の検証は「給与比較」タブ (`app/utils/salary-compare.ts`、給与明細 CSV との突合) が担当。

## 2. 時間データの出どころ

| 値 | 出どころ |
|---|---|
| 実働・時間外・深夜・時間外深夜 (日別) | theearth (web地球号) CSV の日別値をそのまま採用 |
| 法定時間内 | 自前導出: **実働 − 時間外 − 時間外深夜 − 週40超過** (週40超過の控除は §5) |
| 休日区分 (法定/法定外) | 自前分類 (曜日ベース、下記 §4) |
| 週40h 超過 | 自前計算 (§5) |

休日 (isRestDay) の日は全時間 0 として扱う。

## 3. 法定区分と係数 (DEFAULT_WAGE_CONFIG)

金額 = 区分時間(h) × 基本時間単価 × 係数。**円未満は区分毎に四捨五入**し、合計は丸め後の総和。
係数は wage-config (R2 JSON) で変更可能。既定値:

| 区分 (key) | 係数 | 備考 |
|---|---|---|
| 法定時間内 (statutory) | 1.0 | 実働 − 時間外 − 時間外深夜 − 週40超過 (§5) |
| 法定時間外 (overtime) | 1.25 | theearth 日別値 |
| 深夜 (night) | **0.25 (加算分のみ)** | §4 参照。基礎 1.0 は statutory 側に含まれる |
| 時間外深夜 (overtimeNight) | 1.5 | 1.25 + 0.25 の合成 |
| 法定外休日 (nonLegalHoliday) | 1.25 | 既定では未使用 (config 指定時のみ、§4) |
| 法定外休日深夜 (nonLegalHolidayNight) | 1.5 | 同上 |
| 法定休日 (legalHoliday) | 1.35 | |
| 法定休日深夜 (legalHolidayNight) | 1.6 | |
| 週40超過 (weekly40Excess) | 1.25 | 対象時間は法定内から控除済み (§5、二重計上なし) |
| 月60h超過 (overtimeOver60h) | 1.5 (**2023-03 以前の月は 1.25**) | 最低賃金ベース残業代 **と単価マスタ換算の両方** (§6) |

## 4. 日別分類ルール

- **平日 (土曜含む)**: 法定内 = 実働 − 時間外 − 時間外深夜。深夜は 0.25 加算対象の分数として別枠計上。
- **法定休日 (既定 日曜、wage-config で変更可)**: 時間外の概念なし — 実働すべてを法定休日
  (深夜分は法定休日深夜) に計上。
- **法定外休日は既定で使わない (2026-07-18 user 決定、Refs #282)** — 土曜は平日扱い。
  区分と係数の機構は残してあり、必要になったら wage-config の `nonLegalHolidayWeekdays`
  で曜日を指定すると有効化される。会社カレンダー (祝日の個別指定) には未対応。

### 深夜 (通常) は「0.25 加算分のみ」の別枠

深夜時間帯の基礎 1.0 は法定時間内 (statutory) に含まれており、深夜 (night) 区分は
**0.25 倍の上乗せ分だけ**を持つ。したがって恒等式:

```
合計 = 実働全体 × 基礎単価
     + 割増分 (時間外 0.25 / 時間外深夜 0.5 / 深夜 0.25 / 休日系の超過分
               / 月60h を超えたぶんの追加 0.25 — §6)
```

が成り立ち、基礎の二重計上はない。UI の深夜 (通常) 列の計算単価 (@) が基礎単価の
約 0.25 倍になるのはこのため。

時間側の恒等式 (UI で実働と各列を突き合わせる時はこれを使う):

```
実働 = 法定内 + 時間外 + 週40超過 + 時間外深夜 + 法定休日(通常+深夜)
       (+ wage-config で法定外休日を有効化した場合はその通常+深夜)
```

深夜 (通常) だけは上記の**内数** (0.25 加算のための別枠計上) なので加算しない。
休日実働は法定内に入らない (全量が休日区分へ) ことに注意 — UI の最低賃金チェックタブは
法定休日列と**差分列 (実働 − 表合計)** を持ち、差分が 0 以外なら表に出ていない区分への
分類 (法定外休日設定・休日フラグ日の実働・日別データ不整合など) を検知できる (Refs #282)。

## 5. 週40h 超過 (weekly40Excess)

- 週の起算は **日曜** (weekStartsOn=0、決定事項 Refs #244)。
- **週はその終端 (起算+6日) が属する月に計上**する。月初の跨ぎ週は前月末日の実働を含めて
  計算する (前月 summary の days を渡す)。
- 週合計から**法定休日の実働は除外** (法定休日は 1.35 倍側で独立して計上済み)。
- 二重計上防止: 週内で既に割増計上済みの分 (時間外・時間外深夜・法定外休日の実働) を
  40h 超過分から控除し、正の範囲のみ計上する。

```
週40超過 = max(0, 週実働合計(法定休日除く) − 40h − 週内の割増計上済み時間)
```

- **週40超過分は法定時間内から控除する (2026-07-18 案B 決定、Refs #282)**。週40超過の
  時間は日次集計では法定内に積まれるため、控除しないと基礎 1.0 (法定内) + 1.25
  (週40超過) = 2.25 倍の二重計上になる。控除により「法定内 = 割増の付かない時間だけ /
  週40超過 = 1.25 フル」に揃う。時給制でも「1.0 部分を基本給側で払い +0.25 のみ加算」
  (案A) と金額は同値で、どちらも労基法37条 (合計 1.25 倍以上) を満たす — 列の意味が
  揃う案B を採用した。

## 6. 月60h 超過の時間外割増

改正労基法 (中小企業も 2023-04〜適用) の月60h 超 1.5 倍は、**最低賃金換算の残業代理論値**
(minWageOvertimePay / minWageNightOvertimePay) と、**単価マスタ換算の金額**
(computeWageAmounts → amounts / totalAmount / actualOvertimePay / actualNightOvertimePay)
の**両方**に適用している (単価マスタ側は Refs #670 で後から入れた)。

**中小企業の適用猶予: 1.5 倍になるのは 2023-04 の勤務月から。2023-03 以前の月は 60h 超も
1.25 倍のまま** (`OVERTIME_OVER60H_EFFECTIVE_FROM = '2023-04'`)。境界は relay
(`workers/dtako-scraper-relay/src/restraint-wage.ts`) と front (`app/utils/restraint-wage-view.ts`)
に**同名同値で 2 か所**置く (worker から app を import できないため)。relay は `computeWageRow` が
月から実効の設定 (`overtimeOver60h` を `overtime` に揃えたもの) を作って
`computeWageAmounts` / `splitMinWageOvertimePay` に渡す。係数の設定値そのものは変えない。
front は `compareSalaryMonth` が勤務月を受け取り、
`isMonthlyOvertimeOver60h` (橙) も猶予期間の月は false を返す。

**代替休暇 (労基法37条3項) は運用していないため、60h 超は (適用月では) 全額 1.5 倍で計上する**
(オーナー確認 2026-08-26)。運用していないものを分岐で用意すると死に分岐になり、
「運用しているのかもしれない」と次に読む人を迷わせるので、その分岐は置かない。

- 60h 判定の対象 = **時間外 + 時間外深夜 + 週40超過の合算**。
- 時間外軸 (60h まで 1.25、超過分 1.5) と深夜軸 (常時 +0.25) は独立加算。
  60h 超の深夜残業は 1.5 + 0.25 = **1.75 倍相当** (単純な係数切替では表せない)。
- 表示上は 60h 枠を「通常残業 (時間外+週40超過)」から先に消費する按分で 2 列
  (残業代 / 深夜残業代) に割り振るが、これは表示上の慣行であり、按分順序を変えても
  2 列合計は不変 (`splitMinWageOvertimePay` の doc comment 参照)。
- 単価マスタ換算側 (`computeWageAmounts`) も同じ 3 区分を合算して 60h 判定し、
  **超えたぶんだけ**係数を切り替える (時間外・週40超過 → `overtimeOver60h`、
  時間外深夜 → `overtimeOver60h + night` = 1.75 倍相当)。60h 枠の消費順は
  時間外 → 週40超過 → 時間外深夜 で、最低賃金換算側 (通常残業を先に消費) と揃えている。
  **60h を超えていない乗務員の金額は改修前と 1 円も変わらない** (超過分が 0 のため)。
- **画面の橙色 (最低賃金チェック表の時間) も同じ 3 区分合算で判定する**
  (`isMonthlyOvertimeOver60h`、`app/utils/restraint-wage-view.ts`)。
  以前は画面側だけが `時間外 + 週40超過` (時間外深夜を欠く) で判定しており、
  **60h 超なのに橙が点かない行が毎月 4〜9 名**いた (2026-01〜07 実測、Refs #670)。
  **橙は「その月が 60h を超えたか」であって「その月まるごと 1.5 倍」ではない** —
  割増が付くのは超過分だけなので、超過が小さい行では金額はほとんど動かない。
- 単価マスタ側に 60h を入れた版から `WAGE_LOGIC_VERSION` を上げている
  (`app/utils/wage-snapshot-client.ts`)。**保存済みスナップショットは上書きしない**
  代わりに、期間集計で全月が「要再計算」になる — 埋め直しは画面の
  「未保存・要再計算の月を取得 (N)」ボタン。過去の版は「その時点でそう判定した記録」
  として据え置く (親判断 2026-08-26)。

## 7. 最低賃金チェックの比較設計 — 何を含み、何を含まないか

最低賃金法4条3項により、**割増賃金 (時間外・休日・深夜) は最低賃金の対象賃金から除外**して
比較するのが法定の計算。このため:

- **運用上の決定 (2026-07-18, Refs #282)**: 当社は**単価マスタの基礎単価 = 最低賃金**で
  運用しているため、最低賃金チェックタブの「最低賃金換算 / 差」の表示 (グレー行・差行・
  最低賃金割れバナー・行ハイライト) は**全廃**した。表は「対象時間 / @計算単価 /
  単価マスタ換算の金額」のみのシンプル表示。
  - worker (`computeWageRow`) は minWage 系フィールドを従来通り計算して返す
    (表示だけ削除。給与比較タブの 残業・深夜・休日(計算) 列が引き続き利用する)。
  - 最低賃金の設定カード (全社共通履歴) も同タブに残る — 給与比較タブの絶対下限
    チェック用の入力。
  - 訴訟準備の給与比較では、その運用が崩れた月 (単価 ≠ その月の最低賃金、上下どちらも) を
    検出するため、不一致をエラーとして出す (Refs #1133)。
- **廃止 (経緯)**: それ以前に「換算時給 (時間給合計 ÷ 実働) vs 最低賃金」の比較列 (時給列)
  も、分子に割増が全部乗った時給を割増除外前提の法定下限と比べており意味がないため
  削除している (Refs #282)。
- 参考: 法的な意味での最低賃金比較は「基礎単価 ≥ 最低賃金」の判定 (割増賃金は最低賃金の
  対象賃金から除外して比較するのが法定の計算)。単価マスタ = 最低賃金の運用ではこれは
  自明に等号成立する。
- 計算単価 (@) は 金額 ÷ 対象時間 の実額按分 (円/h)。基本給の @ は基礎単価そのもの、
  深夜(通常) の @ は加算分 0.25 倍のみの単価、残業系の @ は基礎込み。

### 給与比較 (支払い実績) の 残業・深夜・休日 と 37条の基礎単価 (Refs #1133)

給与比較 (拘束×賃金の給与比較タブ・訴訟準備の給与比較、`compareSalaryMonth`) は時間を数え直さない。

- **残業時間は wage report が唯一の出どころ**: `WageRow.overtimeMinutes + nightOvertimeMinutes`
  (= 時間外 + 時間外深夜 + 週40超過、§5 §6。`SalaryComparisonRow.overtimeMinutes`)。
  - 金額 (残業・深夜・休日(計算)・37条の理論値) に添える時間は、残業だけでなく**内訳** (`premiumMinutesOf` =
    残業 / 法定時間内の深夜 `minutes.night` / 休日 = 法定休日 + 法定休日深夜 + 法定外休日 + 法定外休日深夜。
    `SalaryComparisonRow.premiumMinutes`)。金額が深夜と休日を含むので、時間も同じ束で出す。
  - タイムカード表の残業時間だけは別 (kosoku 日別の合算。日別には週40超過が無い)。
- **基本給(計算) = 単価マスタ × 法定時間内** (wage report の `wage.amounts.statutory`、`SalaryComparisonRow.sysBase`)。
  給与区分 (月給・日給・時給・不明) に関わらず同じ式で、単価が無い月は計算なし。明細の基本単価 × 日数は使わない
  (日数を掛ければ明細の基本給の項目そのものになり、比較にならない)。差 = 明細の基本給 − 計算 (負 = 明細が下回る)。
- **残業・深夜・休日(計算) = 最低賃金ベースの 残業代 + 深夜の割増 + 休日労働** (wage report の
  `minWageOvertimePay + minWageNightOvertimePay + minWageNightPay + minWageHolidayPay`、
  `SalaryComparisonRow.sysOvertime`。内訳は `sysOvertimeParts`)。最低賃金を基礎額に割増を掛けた絶対下限で、時間は `premiumMinutes`。
  明細の「残業」の区分 (残業代扱い) が 残業・深夜・休日出勤の手当の束なので、計算の側も同じ束を足す (列は増やさない)。
  - `minWageNightPay` = 法定時間内の深夜の分 × 最低賃金 × 0.25 (加算分だけ。基礎の 1.0 は基本給の側)。
  - `minWageHolidayPay` = 休日の 4 区分の金額の和。relay が `computeWageAmounts` を最低賃金の単価で呼んで出す
    (係数は基礎の 1.0 を含む全額・丸めは区分ごと)。休日の分は法定時間内に入っていないので基本給と重ならない。月 60h 超の枠は掛からない。
  - **4 欄のどれかが無い月は計算なし** — 最低賃金が引けない・拘束時間が欠測 (null)、または**休日の欄が無い古い保存物・応答**
    (`minWageHolidayPay` が undefined。`SalaryComparisonRow.wageRowOutdated`)。無い欄を 0 として足さず、画面は取り直しを促す 1 行を出す
    (訴訟準備 = 「拘束の材料を取り直す」/ 拘束×賃金 = 「再計算」)。保存済みの行そのものは捨てない (エラータブ・月ごとの時間の表は古い行でも出る)。
  - 明細の残業単価 × 残業時間は使わない。差 = 明細の残業代 − 計算
    (月給 = 固定残業の人も差を出す。定額が最低賃金ベースの割増を下回っていないかを見る比較そのもの。正の差は「多く払っている」ではないので画面は「月給 (固定残業)」と注記する)。以前の「残業(最低賃金)」列は同じ値なので 1 つに畳んだ。
  - 総支給(計算) = 基本給(計算) + 残業・深夜・休日(計算)。
  - 根拠の行は `sysOvertimeBasisLines` の 1 か所 (両画面が同じものを出す): 時間の内訳 + 金額の内訳 (残業 / 時間外深夜 / 法定時間内の深夜の割増 / 休日労働)。
- **37条の基礎単価** (`computeBaseRate`) = max(逆算の単価, その月の最低賃金)。
  - 逆算の単価: 日給・月給・その他 = 割増基礎の月合計 ÷ **wage report の法定時間内** (`wage.minutes.statutory` = 実働を週 40 時間で頭打ちにした時間。#1169 の直前の分母に戻した)。
    時給 = 明細の時給そのもの。給与区分不明: 出さない。
  - 逆算が最低賃金を下回る月は最低賃金を採用する (根拠の行は `最低賃金 (逆算 R 円/h)` / 時給は `最低賃金 (明細の時給 N 円/h)`。画面は根拠の行を赤にする)。
    欠勤などで実働が短い月は、逆算の単価が従来 (173.8h 割り) より高く出る。
  - 理論値 = `round(残業・深夜・休日(計算) × 基礎単価 ÷ 最低賃金)`。残業・深夜・休日(計算) は wage report の最低賃金ベースの金額で、割増の規則 (1.25 / 60h 超 1.5 / 深夜 +0.25 / 休日の係数 / 猶予期間) は wage report が正本 — front で実装し直さない。
    深夜の割増と休日労働も割増の基礎が同じなので、同じ倍率 (基礎単価 ÷ 最低賃金) で出る。
    最低賃金を採用した月は 残業・深夜・休日(計算) そのもの。割増額は基礎額に比例するが、relay は区分ごとに丸めてから足すので、基礎単価が最低賃金を上回る月は relay の式で直接計算した額と数円ずれうる。
  - 出せない月 (理由つき): 給与区分不明 / 時給の単価なし / 割増基礎 0 / 法定時間内 0 / 最低賃金が引けない / 拘束時間が欠測 / 拘束の材料が古い形 (休日の欄が無い)。
- 根拠の文字列は `baseRateBasisText` の 1 か所 (両画面が同じものを出す)。基礎単価の値は 1 行上に出るので繰り返さず、逆算を採用した月は `割増基礎 N 円 ÷ H`、時給を採用した月は `明細の時給`。式の説明 (割増基礎 ÷ 法定時間内) は列見出しの title・注記が持つ。

### 月次集計タブ・CSV エクスポートの列名 (Refs #938)

上の全廃 (#285) は**最低賃金チェックタブだけ**に効いていて、**月次集計タブの表と CSV は
取りこぼしていた** — `換算時給` / `最低賃金差` という列名のまま出続けていた
(表の 2 列は内訳列の `expandWage` ゲートの外なので、内訳を畳んだ既定状態でも常に見える)。
結果、同じ `report` から **最低賃金チェックタブは「この表は最低賃金との差分を出しません」
(#937 の ⚠ 注記)・月次集計タブと CSV は「最低賃金差 = −○○円」**という、正面から矛盾した
2 つの出力が出ていた。

**列名を実態に合わせる (値は 1 円も変えない)** で解消した:

| 旧 | 新 (CSV) | 新 (月次集計表の見出し) |
|---|---|---|
| `換算時給` | `総支給時給(割増込)` | `総支給時給` |
| `最低賃金` | `最低賃金` (変更なし) | — (表には元から無い) |
| `最低賃金差` | `総支給時給−最低賃金(法的判定ではない)` | `総支給時給−最低賃金` |

- **なぜ列ごと落とさず値を残すのか**: 総支給額 ÷ 基礎時間 という値そのものは
  **人件費単価の検算や月次の傾向把握には使える**。使えないのは**法的な最低賃金判定
  としての読み方だけ**なので、消すべきは値ではなく誤読を招く列名。既存の CSV 取り込み
  (列位置固定) を壊さない利点もある。
- 列名と「何であって何でないか」の 1 文は `app/utils/restraint-wage-view.ts` の
  `MONTHLY_CSV_WAGE_TAIL_HEADERS` / `GROSS_HOURLY_CAVEAT` に集約し、CSV の列名と
  月次集計表の `title` 属性が同じ定数を引く。**片方だけ直せる状態だったことがこのズレの
  原因**なので、再発を構造で止める。
- **TS のフィールド名 (`hourlyEquivalent` / `minWageDiff`) は改名していない** —
  relay → front のワイヤ上のキーなので、改名すると deploy skew の間だけ両側が食い違う。
  代わりに定義箇所 (relay / front の `WageRow`) に doc コメントを置いた。

### 給与実績側 (給与比較タブ) の支給項目区分 (Refs #278)

**月の突合 (Refs #282)**: 給与明細 CSV の「給与・賞与名」の年月 (例 `2026年 8月`) は
**支給月ラベル**。当社は月末締め・翌月払いのため、勤務月 m の画面には CSV の m+1 月
ラベルの行を突合する (給与比較タブ・最低賃金チェックタブの 基本給(給与)/残業代(給与)
列とも共通。実装は `salaryMonthRows`)。

給与明細 CSV の支給項目は「割増賃金の基礎 (労基法37条) × 最低賃金の対象 (最低賃金法4条3項)」
の 2 軸で 5 区分に分類する (`SalaryItemCategory`):

| 区分 | 割増基礎 | 最低賃金対象 | 例 |
|---|---|---|---|
| base | ○ | ○ | 基本給・職務手当 |
| overtime | — (割増そのもの) | × | 残業・深夜・休日出勤手当 |
| minwage-only | × | ○ | 住宅・別居・子女教育手当 |
| premium-base-only | ○ | × | 精皆勤手当 |
| excluded | × | × | 通勤・家族手当、臨時の賃金、賞与 |
